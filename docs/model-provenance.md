# Model and sample provenance

The maintainer supplied these artifacts with `CCP_New_UI` and authorized regular
Git distribution for this migration. Exact shipped bytes are listed in
[`models/manifest.json`](../models/manifest.json): path, byte count and SHA-256.
The manifest is validated before commit and in CI. Each file is below GitHub's
100 MiB individual-file limit. Approximately 203 MB of weights are intentionally
not Git LFS pointers; clones must have enough disk space.

- `models/opt2`: Opt2 assembled chart detector at 1280/1536 input sizes, FP16
  TorchScript and FP32 ONNX exports. The weights came from the maintainer's tested
  native codebase; no new training or weight conversion is performed here.
  Preserved embedded TorchScript metadata explicitly names **Ultralytics 8.4.92**,
  task `obb`, and **AGPL-3.0**. Generated module code also names Ultralytics.
  [Model notices](../models/NOTICE.md) and [the license](../models/LICENSE-AGPL-3.0.txt)
  are bundled. Upstream source is pinned to commit
  [`c006801d6daa39284724666b3dbef42b85dded67`](https://github.com/ultralytics/ultralytics/tree/c006801d6daa39284724666b3dbef42b85dded67)
  (tag `v8.4.92`). The model files are not represented as MIT-only.
- `models/plane`: supplied YOLO-named 512 plane detector ONNX. Its name alone is
  not proof of a particular training framework, dataset or license.
- `models/apply`: trilinear 3D LUT application graph generated by the project
  helper `scripts/export_lut3d_onnx.py`; zero-byte external-data companion retained.
  Migration validation found that its original fixed 17³ input rejected the
  engine's 33³ grid. It was regenerated with symbolic grid dimensions (PyTorch
  2.13.0 CPU / ONNX 1.22.0 export tools, opset 17 / IR 9) and checked against the
  CPU interpolator at 17³ and 33³. These export tools are not runtime dependencies;
  LibTorch remains 2.9.1. Detector inference graphs and tensors are unchanged;
  artifact bytes differ only because local path metadata was sanitized.

## Portable metadata

On 14 October 2026, `scripts/sanitize_model_metadata.py` removed local training/
export path prefixes from four Opt2 artifacts. ONNX changes affect only metadata
properties: canonical model bytes with those properties removed are identical,
including all 214 initializers in each graph. TorchScript changes affect only
debug path strings and extra config descriptions/paths. All 535/545 other archive
entries, including inference code, constants and tensor storage, are byte-identical.
The original files in the supplied native checkout were not modified. License,
author, framework version, architecture, dimensions and class labels are preserved.

Training dataset identifiers, consent/license records, base-weight ancestry,
training scripts/commit and independent evaluation for the detector artifacts
were not present in the imported codebase. They remain **unverified**, not
inferred. The project MIT license must not be represented as proving all upstream
weight rights. The maintainer requested proceeding without additional provenance
questions; missing records remain disclosed, not invented or certified. That
request does not replace the preserved upstream license terms.

The five public photographs already existed at `test_images` in the legacy
repository; paths and bytes are unchanged. `Blank.JPG` is only an FFC blank
reference. Sample photographs are demonstrations, not certified measurement
truth. No private Downloads attachments or derived private reports are imported.
Additional chart/profile/orientation coverage uses generated fixtures.

Canonical reference tables and their sources/editions are audited in
[color-science-validation.md](color-science-validation.md). They are not model
training weights and should not be substituted with screenshot RGB swatches.
